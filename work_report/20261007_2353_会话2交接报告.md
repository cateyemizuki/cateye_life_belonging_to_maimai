4. **红先绿后**：新行为用例先跑出红（必要时以 HEAD 前缀实现重放），再转绿；红绿输出落盘 scratch 并在报告引用。
5. 提交由**主会话**执行（workflow 子代理禁 commit）；文档（README/USAGE/EMOTION_MAPPING/计划书勾选）随单元同批提交。

### 本会话实测的坑（新会话直接避开）

- **workflow SPEC 字符串里严禁出现 Markdown 反引号**（会提前终止模板字符串，编译报一堆伪错误）——用「」或裸名。
- `report()` 的空数组字面量推断 `never[]` → 先声明带 interface 的变量再传。
- **scratch 不是 git 仓库**：子代理/复核无法 diff 用例，证据靠 `.out` 落盘 + 摘要行比对；用例编号连续追加（当前至 125）。
- workflow 完成通知可能先后出现 stopped/completed 两条——以 `GetWorkflowRun` 快照为准。
- Bash 工作目录每次调用后重置（Shell cwd was reset）——长命令用 `cd … && …`；Git Bash 的 `/tmp` 与原生 Python 的路径不互通，临时文件用显式盘符路径。
- `_MODULE_BY_PREFIX`（门面审计）要求处理器方法名以 plan_/mai_/qzone_/emo_ 开头，且处理器源码必须解析出服务束属性链；跨 mixin 助手（如 `_qz_is_admin`）可直接 self 调用。
- 共享 behavior 脚本的硬编码日期会跨日腐坏——新用例一律 `datetime.now()` 或注入时钟，勿写死日期。
