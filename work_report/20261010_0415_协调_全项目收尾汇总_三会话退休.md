### 7.2 新缺陷登记 **P7：affection.current_level 传输形态校验失败（既有 as-built 缺陷）**
- **根因**（用户方已核码，协调采信）：`companion/config.py:344`
  `current_level: Literal[0, 1, 2]`——整数字面量枚举。宿主传输形态为字符串（WebUI 表单控件提交
  `"1"`，或 config.toml 手写成 `current_level = "1"`），Pydantic v2 的"数字字符串宽松转 int"只对
  int 字段生效、对 Literal 成员按值+类型精确匹配 → `"1" ≠ 1` → literal_error → 整个
  CateyeSuiteConfig 校验失败 → 宿主回 E_BAD_PAYLOAD（配置校验请求失败，非插件运行崩溃）。
- **事实**：全仓唯一整数字面量 Literal（relation_type/evaluate_mode/inject_scope 均字符串枚举不受影响）；
  该行自基线 `a1a43b0`（R0+M0 动工前）一字未改——既有缺陷，非发布化/清洗引入；下游消费点
  （plugin.py:79、services.py:97/210）本就 `int(...)` 使用，收成 int 行为不变；
  离线门禁盲区：smoke 用全默认构造，从不喂传输形态 payload。
- **临时规避**：config.toml 写不带引号的整数 `current_level = 1` 后重试；若 WebUI 保存仍报错则必须代码侧修。
- **修复建议（推荐 A）**：保留 `Literal[0,1,2]`，加 `@field_validator("current_level", mode="before")`
  前置校验器把 `"0"/"1"/"2"` 归一为 int（strip 后整集匹配），其它仍按 Literal 拒绝（"3"/"x"/5 照旧报错）；
  方案 B（int + ge=0 le=2）会使 JSON schema 枚举变整数、需同步 USAGE.md:476 类型列，不作首选。
- **随附**：回归守卫进 `scratch\smoke_test_lbm.py`——断言传输形态 `{"affection":{"current_level":"1"}}`
  通过、`"3"/"x"` 仍拒；CHANGELOG「修复」增用户向条目。
- **适用面与去向**：companion/config.py 双身份同源——主线 master 与 release/lbm-1.0.0 **都需修复**。
  三会话已退休/ retiring，由用户裁定执行方式：①用户自行按上述 A 直改（改动约 7 行+守卫用例）；
