## 一bis、「同源」的准确含义（子代理独立比对抓到的差异）

对两棵树的全部 `.py` 做身份串归一化（`cateye_test_`↔`lbm_`、manifest id、显示名、`0.2.0`↔`1.0.0`、UA）后
逐文件比对，**存在 4 处发布树独有的加固，开发树没有**（均属 R6「数据目录绕出」修复的其余面；
本轮只把其中 `planning/schedule_image.py` 一面回灌了 master）：

| 位置 | 发布树（本树） | 开发树（master） |
|---|---|---|
| `cateye_dashboard.py` 出图 `output_dir` 缺省 | `tempfile.gettempdir()` | `Path(__file__).resolve().parent`（插件代码目录） |
| `companion/services.py` `_data_dir` 缺失回退 | tempdir + `logger.warning` | `Path(".")`（宿主工作目录） |
| `emotion/service.py` 同上 | tempdir + warning | `Path(".")` |
| `planning/goal_manager.py` `data_dir=None` | tempdir + warning | `Path(__file__).parent` |
| `planning/cleanup_service.py` | `from typing import TYPE_CHECKING, Any, Optional` | 缺 `Any`（`from __future__ import annotations` 下不炸，属标注补全） |

**结论：合并后本树 = 开发树的配置整理轮 + 本树原有的 4 处隔离加固，是本树"严格超集"。**
不存在回退；开发树（已冻结）缺的这 4 处不必回灌（维护基线已在本树）。行为门两侧均不触发这些回退路径
（测试都显式传 `_data_dir`/`output_dir`），故门禁全绿不构成"同源"的证明——本节的逐文件比对才是证明。
两树还有若干纯文档/注释差异（配置描述里的命令名、UA、docstring 等），无行为影响，不逐一登记。

**另修一处失真注释**：`suite_config.py` 原注释称 `SUPPORTED_CONFIG_VERSION`「与 `_manifest.json` 的 version
保持同步」，实际两树都不等（本树 1.0.0 vs 1.1.0）。已改写为"**与插件版本解耦**，两者不等是预期状态"
并保留"何时才可递增"的口径。
