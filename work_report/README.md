> 建目录时间：2026-10-05 02:27（本机 UTC+8）

## 一、这个目录放什么

**此后每一轮针对 `cateye_test` 的工作都必须在这里留一份报告**，无论这轮是改代码、改文档、跑宿主验证、
还是只做只读评估。报告是交付物之一，与代码/文档同批完成。

## 二、命名规范（强制）

```
<YYYYMMDD_HHmm>_<主题>.md
```

- **时间戳前置**：取报告完成时刻的**本机时间（UTC+8）**，格式 `YYYYMMDD_HHmm`（例 `20261005_0227`）。
  前置的目的是让目录按文件名即可排序（等价于按时间排序）。
- **分隔**：时间戳与主题之间用单个下划线；主题内部可用中文、字母、数字、点号，**不要**用空格与斜杠。
- **主题**：中文短语，能一眼看出这轮做了什么（例：`MAINTENANCE_PLAN_10.25修订与完工评估`）。
- **同分钟多份**：在主题后加 `_2`、`_3`。
- 示例：`20261005_0227_MAINTENANCE_PLAN_10.25修订与完工评估.md`

## 三、每份报告必含的字段

| 字段 | 要求 |
|---|---|
| 时间戳 | 报告完成时刻（本机 UTC+8） |
| 会话性质 | 改代码 / 改文档 / 宿主验证 / 只读评估（可多选） |
| 依据 | 读了哪些上游文档与数据（带**绝对路径**） |
| 任务与产出 | 逐条列，产出必须带**绝对路径**与字节数/行数 |
| 实测证据 | 命令 + 数字 + 文件路径。**不得只写结论**；抽查类证据要写清检索范围与命中数 |
| 计划书修订明细 | 逐处列出改了什么（清退/新增/订正），含章节号 |
| 本次会话的裁量 | 有解释空间的处理（如"除归档节外"如何理解），如实列出供用户否决 |
| 遗留与未完成 | 每项写去向（哪个里程碑/挂账号），不写"待办"了事 |
| 校验结果 | 跑了什么、退出码、数字是否与断言一致 |

## 四、写作要求

1. **单文件自足**：报告必须能被独立读懂；引用别处要带路径与行号，不得只写"见某处"。
2. **不美化**：判定为 FAIL/warn 的、没做完的、口径有歧义的，原样写。首份报告（L5 判定）的
   "如实保留字面 FAIL" 是本文档体系的既定风格。
3. **收尾前写**，写完再回复用户。
