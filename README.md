# 属于麦麦的生活

> 当前版本 **3.17.34**。一个 MaiBot 插件，让麦麦拥有自己的日程、关系、QQ 空间与情绪。本文只描述当前能力；版本沿革与逐批变更记录见 [CHANGELOG.md](CHANGELOG.md)，不以本文历史段落判断部署版本。日程侧：普通小事件（可编辑 `mappings/initial_events/` JSON 库 + 生成池）作为正常滚动候选参与选取，待机仅为短空档兜底；人设驱动的日程偏好低频批量评估、普通滚动 0 LLM；模块联动（刷视频/刷QQ）保留独立预算。

## 当前能力概述（v3.17.x）

- **日程规划**：模型每天只生成 3~6 条稀疏「日意图（spine）」，滚动运行时在意图框架内推进成真实活动，当前活动从唯一真源注入对话；生活状态（精力/饥饿/专注/压力/社交电量）与睡眠引擎随日程总开关运行，硬约定不因晚起顺延。命令族 `/lbm_plan`、`/lbm_life rolling`。
- **虚拟陪伴**：好感度 0~200 养成；有界早安/中午问好/晚安、状态·情绪·好感驱动的想念、刷QQ随口联系、视频分享与点播完成通知。所有激活 planner 的主动行为经**主动统一入口**登记（3.17.14），replyer 按聊天类型×发起原因定制改写文案；3.17.17 起原子领取+触发前登记，真实来信轮逐字不变。每日主动预算、静默时段与问候去重口径不变。命令族 `/lbm_mai_*`。
- **QQ 空间**：按日程节奏自动发说说（多级判定链+模型严判）、四模式配图、自动回评（含楼中楼，CGI 直连）与评论基线提醒、点赞；看过的视频经判定+高清截图资产+独立文案发视频帖（出厂影子模式，auto 经完整门控）。视频说说文案为自然个人分享口吻，不附标题/UP 等元信息署名（3.17.17）。命令族 `/lbm_life`。
- **情绪维护**：按人设推导愉悦度/唤醒度/支配感三维基线，随聊天与事件持续起伏，睡眠冻结结算，情绪原因有时效并可注入；`/lbm_init` 统一初始化、`/lbm_emotion_config` 查看与重置。
- **视频观看**：内置 B 站观看（长链接/b23 短链/QQ 小程序分享文字解析、stream 优先采样、拼图视觉理解+内容描述与观后感、观看记忆防重、点播完成通知交回原发起聊天）；日程「刷视频」小事件按兴趣从热门排行榜自动选片，无合适候选如实跳过。工具 `lbm_watch_bili_video`。
- **娱乐面板 / WebUI 生活面板**：此刻/日程/历史/娱乐/系统五栏；固定框架+SVG 翻页、此刻心情与睡眠双列、历史心情曲线与采样表、娱乐页最近观看+兴趣话题+空间最近动态（3.17.13–3.17.15）；mast 自适应收缩、时间戳空间不足省略号截断（title 全文）不溢出圆角框（3.17.18）。只读投影、30 秒刷新、快照导出/导入，不触发模型调用或业务写入。
- **联动层**（3.17.16）：根目录 `linkage/` 跨插件联动协议与注册表，首个适配器 `cateye_screen` 屏幕感知——主动聊天/问候触发前看一眼陪伴对象电脑并注入旁白（仅目标私聊、出厂关闭，服务缺失/离线降级不阻断触发）。

## 已知限制

- QQ 空间依赖 SnowLuma 适配器（NapCat 画像不支持 QZone API）；动作面拿不到评论正文，自动回评走 CGI 直连，cookie 不可用时降级为「有新评论」提醒；好友动态不含 tid，无法点赞好友说说。
- 屏幕感知需要对端 cateye 统一连接插件且客户端在线；屏幕内容只注入陪伴目标私聊，绝不进群聊/其他私聊/空间；出厂关闭。
- 视频观看是采样理解，不假称逐帧看完、不做音频转写；显式 p>1 当前拒绝，多媒体分段尚不拼接；ffmpeg/视觉任务不可用时如实降级为文本来源。
- 适配器受理只表示已提交，不代表送达；超时、重启中断或结果不确定时保守防重、不补发（视频帖、分享卡片、点播通知同口径）。
- 主动行为受每日预算/静默窗/忙闲门控约束；已登记例外：例行问候免预算、qzone 评论提醒免预算、点播完成通知属回执不计预算。
- 目标私聊流未解析期间（每 60 秒重试）没有任何主动消息；先与目标 QQ 互发一条消息通常即可解析。

日程意图按所属日期判断窗口，不把未来跨午夜的尾段折回当天凌晨。模型不可用时，兜底晚餐安排在入睡前3–5小时的两小时窗口；极饿时仍可选择应急进食，已开始的跨午夜活动继续按真实日期推进。

### 当前配置说明

- “屏幕感知”独立放在“陪伴模块”后：`[screen].enabled` 控制主动聊天前自动查看，`tool_enabled` 控制按需屏幕工具，二者独立且出厂均关闭；`blur` 为模糊半径，`scope` 为主屏或全部屏幕。旧 `[patrol].screen_*` 自动迁移，显式的新段值优先。
- `lbm_peek_companion_screen` 只绑定已由宿主解析的陪伴目标私聊，执行前后再次核验；不接受目标参数，不控制电脑，不发送截图。返回截图时间范围和文字，离线/失败时如实说明。首次尚无会话绑定时不注册，解析就绪后下次宿主热重载生效；更换目标时同样保持关闭，直到新绑定就绪。

- 「麦麦互动」控制角色动作与详情动画；「数据展示」控制最近变化的条数和状态、睡眠债显示阈值。旧位置的设置在内存中兼容迁移，页面读取字段保持不变。
- 提示词保留12项常用文案：想念说明、活动/日常分享、屏幕理解/旁白、私聊文案、日程追加要求、早晚安、睡眠语气及空间文案。43项内部协议由代码维护，旧配置覆盖不再生效。
- 告状接收顺序：显式接收人→陪伴目标→宿主全局管理员。当前宿主尚未提供全局管理员字段；前两项均不可用时不发送，不以插件管理员代替。
- 视频模块不提供配置待看列表，不修改配置文件来消费或清理视频；直接链接点播、缓存和完成通知仍可用。日程无真实候选时正常跳过。

## 视频观看（内置）

工具支持直接传入长链接、b23短链或QQ小程序分享文字，`resolve`可取得真实BV，禁止模型猜测BV。默认`source_mode=stream`：直接按时间点读取CDN，不先下载整片；可显式切换`download`。`sampling_mode=seek`快速抽样或`paced`按真实时间采样，均串行、低优先级、单解码线程。stream失败不暗中下载全片。

准入按**预计提交的拼图张数**：默认每25秒一帧、16帧/张4×4拼图、最多16张，约106分钟。超出会说明实际所需张数，可自行调整间隔/拼图数，不静默稀释。只记录真实Token，不承诺固定Token消耗、不设插件输出Token上限。download默认256MiB保护值不影响stream准入。任务仍有3小时总截止，队列深度3；旧时长/散帧上限安全忽略。

点播提交后提示麦麦先自然确认一句，再继续交流，不强制停止planner；完成/失败由持久通知记录交回**原发起聊天**。这与生活中的主动分享分开：不广播、不发给默认陪伴对象、不新增主动次数；不确定投递不重试。status/result只供用户明确询问时查询，后台不调用模型轮询。配置分组显示为“视频观看”。画面仍为抽样，不假称逐帧看完或听过音轨。

拼图识别后另发一个文本请求，结合视频标题、UP主、简介、真实画面理解与采样范围整理内容描述，有公开字幕时作为补充；未覆盖的情节和不确定小字不补造。观后感依据真实读取来源生成。交给planner的仅有标题、UP主、时长、完整内容描述与观后感，不传逐帧识别记录，也不再由插件按固定字数截断。

观看记忆只缓存BV号与上述文字，默认保存15天，读取不续期。再次提交同BV会明确告知“以前看过”，不新建任务、不调用模型、不追加完成通知；只有用户明确要求重新观看才传 `rewatch=true`。启动及既有生活tick清理过期缓存，按原保存时间迁移旧缓存；旧记录缺独立描述时如实标缺，不补跑模型。任务历史仍按原有规则维护，不以另一同BV任务的缓存替代指定任务结果。

## 这个插件是什么

「属于麦麦的生活」把四件互相关联的事交给麦麦自己完成：

- **日程规划**：每天生成一组「日意图（spine）」并由滚动层执行成真实活动，把「现在在做什么」自然地注入对话。
- **虚拟陪伴**：维护与陪伴对象的好感度，在合适的时间问候、想念与搭话。
- **QQ 空间**：按日程节奏自动发说说、配图，并回复评论。
- **情绪维护**：让情绪随聊天起伏，为回复提供底色与描述。

模块共享同一份真实作息与活动。发往目标陪伴私聊的主动打扰（巡检/想念/条件分享/告状）受每日预算约束，QQ空间另有上限；主动私信工具已于2026-11-03移除，persona主动发言无直发绕过。已登记例外：例行早/中午/晚问候免预算（独立闸门去重）、qzone评论提醒免预算（M11授权，降级提醒）、视频完成通知属点播结果回执不计预算。详见DEV_GUIDE预算覆盖面契约。

## 安装

1. 把插件目录放进 MaiBot 的 `plugins/`（目录名建议 `cateye_life_belonging_to_maimai`）。
2. 重启 MaiBot，或在插件管理里重载插件。
3. 在 WebUI 的「陪伴模块」里填写 `target_qq`（`[patrol]`）。保持默认占位值 `123456789` 时不会主动私聊任何人，`/lbm_mai_*` 命令不可用；管理员命令仍由 `admin_users` 决定。
4. 如需从 QQ 使用管理员命令，在「管理与日志」（`[admin]`）里填上你的 QQ 号；留空时仅本机控制台可用。
5. 依赖 `httpx` 与 `Pillow`。Pillow 只用于渲染日程图与状态图，缺失或渲染失败时自动降级为纯文本。

屏幕感知、QQ空间、周结大事记保留独立开关；事件库使用日程段的`event_catalog_mode`控制，off只取内置池。日程总开关启用后，生成/跨日/意图分类和注入优化固定适用，生活状态只使用目标趋近结算，正常睡眠始终动态。午休只对QQ空间按真实活动静默。

屏幕感知默认只看主屏（`[screen] scope=main`，与旧版行为一致）；TA 常在副屏上干活时可改 `all`——对端（cateye 统一连接插件 v1.1.0+）多屏时逐屏抓取，全部截图一次交给视觉模型分屏概述；对端过旧、单屏客户端或负载超限自动降级时，`all` 退化为只看主屏，与 `main` 等价。

**前置条件**：QQ 空间需要 SnowLuma 适配器（NapCat 画像不支持 QZone API）；屏幕感知需要「cateye 统一连接插件」且对方电脑上的客户端在线。目标私聊流解析不到时，插件每 60 秒重试一次，期间不会有任何主动消息；先与目标 QQ 互发一条消息通常即可解析到。

WebUI 段键对照见上文「配置入口」（19 段：插件/陪伴模块/屏幕感知/好感度/日程系统/日程系统·高级设置/日程主动行为/事件与分享概率/情绪系统/生活状态/QQ 空间/空间视频/视频观看/视频分享/LLM 调用/提示词（高级）/管理与日志/数据展示/麦麦互动）；事件库不再是独立段，配置平铺进 `[schedule]`。

## 生活面板详情

页面左下角有一只**贴角冒头**的常驻麦麦（只露头顶和眼睛，默认 128px）：鼠标指向露出的它，它会先向上弹起、再落到左下角底部站稳（落地后身体水平）；落稳后按住会渐渐压扁并**保持压扁**，松开才从当前形态连续回弹；指针远离左下角约半秒后自动收起、退回贴角探头姿态。触屏设备点按探头即弹出、点空白收起；键盘 Tab 聚焦后 Enter/Space 同样可弹出或触发回弹。详情打开期间它保持可见（只是暂停捏捏），关闭后一切照旧。

每个数据板块左下角有一个详情入口小麦麦（同样贴角冒头，默认收起）。**鼠标悬停即可临时预览**详情（不抢焦点、不锁滚动），移入面板保持阅读，移开片刻自动收起；**点击固定**（锁定滚动、焦点管理生效），再点同一入口取消固定；点击另一入口直接切换。详情面板以入口为原点展开/收回，一条气泡尾把面板和入口连在一起；入口始终在原位清晰可见。按 Esc（说明 tooltip 打开时先关说明）、点击面板外背景或右上角关闭按钮关闭。背景为轻微模糊+低强度遮罩，背后内容仍可辨认。打开期间 30 秒只读刷新照常进行，不会重置滚动位置；历史曲线、日期选择、快照导入仍可使用。宿主内采用viewport布局，页面内部滚动，避免手机底栏被宿主导航遮住。

「日程」栏的时间线改为纵向列表：计划（虚线轴点）与实际（实线轴点）同列展示、徽标区分，中断标红虚线、跨午夜条目续到次日、进行中的活动以当前时刻收尾；「最近变化」折叠组列在板块详情末尾，展示最近真实发生的状态与活动变化（估算采样点不入列）。日程在空闲时段可能选中「刷视频」小事件（可中断的娱乐活动）：观看能力内置在本插件；自动候选已接线（按麦麦兴趣从B站热门排行榜匹配并去重），无合适候选时该次事件如实跳过，用户也可直接通过链接点播。互动与详情的展示参数（常驻麦麦尺寸/探头角度/收起距离、背景模糊半径、最近变化条数等）由配置段 `[maimai_interaction]` 控制，默认值即可使用。

## 模型输出与 Token 统计

插件不再设置模型输出长度或每日 Token 限制；输出长度完全使用宿主任务配置。旧限制键自动忽略，其余任务路由、温度、超时、主动消息每日次数和事件池规则保留。

调用次数统计收到宿主响应的请求，包含失败；Token只累计宿主明确回传的用量，缺失不推算。四类调用为正常回传、成功但无用量、失败调用、旧记录；“缺用量来源调用”是独立提示，可与失败重叠。WebUI提供说明按钮，PNG展示相同口径。

## 四个模块

> **架构定位**：`planning/` 不只是并列业务模块之一，它同时承担**时间/日程领域内核**——`time_utils`、`schedule_query`、`schedule_anchors`、`schedule_items` 被陪伴、情绪、空间等模块共用。其余模块的时间窗口判定必须复用这些实现，禁止自建副本（结构守卫 `test_backend_boundaries.py` 已把存量跨模块导入逐条登记并禁止新增）。

### 日程规划

- 每天由模型只生成 3~6 条「今天想做什么」的稀疏意图（spine）+ 硬约定 + 作息锚点，其余时段交给滚动层按本地规则推进，不再一次排满全天。
- `[schedule] wake_time` / `sleep_time` 仍是起床与入睡锚点；`no_sleep_mode=true` 时睡眠窗内不生成任何活动。
- 每份日程**进账即成为 bot 的作息周期**：上一份退为「上轮边界」，新的「本轮开始（≈起床）/本轮结束（≈入睡）」持久化生效；真实睡眠会话结束时会用真实醒来时刻校正周期。
- 当前活动只有一个真源：滚动运行时的真实 episode。空闲时如实「没有安排中的活动」，不按时间窗或旧日表编造。
- `/lbm_plan list` 查看时刻表图，条目带日程属性标签；当天无日程时会先自动生成。
- `/lbm_plan regenerate [额外要求]` 重建今日日意图；`delete` 删除指定目标；`clear` 清理旧日程。
- 模型生成失败时使用 spine 模板兜底，模板同样按你的作息锚定。
- 聊天频率随日程属性变化，倍率可在 `mappings/schedule_properties.json` 中调整。
- 节假日可写入日程块头部，也可让生成时考虑节假日（两个独立开关）。
- 在对话里提出日程变动时，bot 会判断接受、记为未来约定或拒绝；固定时间的硬约定**不因晚起顺延，迟到如实记录**。

### 生活状态 / 睡眠（随日程总开关）

- **滚动执行与生活状态**：精力/饥饿/专注/压力/社交电量五项连续状态（纯本地规则推进，零模型调用），按 5 分钟节奏在日意图框架内「走一步看一步」地选活动；活动进度随实际进行时长增长（上限 0.95），空闲时段如实显示无活动；被打断的活动进恢复池，可能恢复也可能不了了之。
- **情绪-生活双向联动（可选，`[life_state] emotion_modulation_enabled`，默认关）**：情绪（愉悦度/唤醒度/支配感）按平滑读数轻微加快或减慢五项生活状态的变化速率；活动完成或被打断也会小幅影响情绪。映射表固定 `mappings/emotion_life_modulation.json`，不提供路径配置键。
- **睡眠引擎（随日程总开关，无独立开关键）**：到最早起床时间后按精力阈值（默认 0.75）决定是否赖床，最晚 `[schedule_advanced] lie_in_max_until`（默认 12:00）必起；硬约定**至少提前 30 分钟**醒，**固定时间硬约定不因晚起顺延、迟到如实记录**；**正式起床结束当前睡眠会话、记为完成、不进恢复池**；半夜短扰只统计，**确认清醒 ≥5 分钟才重置连续睡眠段、会话仍保留**。睡眠中热关闭日程，会以关闭真实时刻结束会话并交回停止状态；**重新打开不会复活旧会话**。
- **QQ空间午休静默**：仅依据真实执行中的午休活动，不将跳过的计划或普通休息当作午休。陪伴侧不再有午休静默开关。
- **活动日志**：实际发生的事记入日程库（计划、进行中、完成、被打断、暂停、放弃、跳过），「我在做什么」只从真实发生读。
- **调试命令**：管理员可用 `/lbm_life rolling` 命令族（status / state / episodes / spine / sleep / preview 六个子命令）纯只读地查看滚动层与睡眠引擎状态；日程未启用时提示「日程未启用」。

### 事件库（可选，默认 off）

- `[schedule] event_catalog_mode` = `off`（只用内置池）/`manual`（仅手动刷新）/`auto`（到期后台生成）。
- 生成数量由三时段「可复用 / 一次性」六键配额决定（每段每池 0–12）；池上限 = 内置数 + 配额和（派生，3.17.6 起独立总配额 `max_pool_events` 已退役）；内置池至少 3 条兜底、生成项 `llm_` 前缀、全量校验通过才替换。
- 事件文件写坏/缺失/版本不认识时回退内置池并保留 `.bak`，不会覆盖你的用户文件。

### 统一初始化

`/lbm_init`（全量：情绪 + 事件 + 状态/睡眠 + 频率）、`/lbm_init emotion`（强制情绪）、`/lbm_init events`（强制刷新事件库）、`/lbm_init status`（只读）。阶段互相独立，失败不拖垮其他阶段；汇总写数据目录 `life_init.json`。旧 `/lbm_emotion_init` 命令已在 3.0.0 删除，请改用 `/lbm_init emotion`。

### 虚拟陪伴

- 好感度 0~200，默认五档；档数、档名与区间由 `mappings/affection_presets.json` 定义。
- 早/晚安由作息周期驱动：早安在起床后的漂移点，晚安在入睡期限前的漂移点发出（期限 = 本轮日程的入睡时刻，跨 0 点照算真实时刻）。早安期限另受有界上限 min(`greeting_morning_latest` 默认 10:00, 醒后 2 小时) 钳制，超界静默放弃留诊断（3.2.0）。中午问好（`greeting_noon_enabled`，3.2.0）仅目标陪伴私聊 12:00-13:00 窗内首 tick，双重去重落盘、热重载不重发。
- 问候始终免主动消息预算，也不受静默时段拦截。
- 问候闸门按三流分离（判定窗都是「上份日程开始 → 本份日程开始」这类周期窗，不看日历 0 点）：
  目标私聊**无条件**（只看陪伴模块开关，不再要求当日有消息）；群聊早安过**硬闸**（判定窗内 ≥1 条非 bot 消息，必要性开关开启的话再叠加「今天日程第一个条目时段内有人主动开口」）；其他私聊早安 = 判定窗内对方发送条数达门槛（默认 5），晚安 = 早安已发**连锁**或对方发送达晚安阈值（默认 5）二选一。
- 群聊早安本轮没开口，当晚群晚安**连锁硬性失效**；过了掷点才达标的补发还有**冷静期**——bot 本会话最近一条消息距今 ≥ `greeting_min_silence_minutes` 分钟才开口，一直不满足则到期仍弃。
- **早安沉默闸**（`greeting_morning_silence_hours`，默认 2 小时，0 = 关闭）：今日第一日程（周期起点）前 N 小时内 bot 自己在该会话发过消息 → 该会话本周期跳过早安（三流统一生效，含目标私聊；不掷点、不建条目）。
- 陪伴巡检与想念只发生在目标私聊，受每日预算、最小间隔、用户冷却与静默时段约束。想念为状态·情绪·好感驱动的概率触发（3.2.0 重写，不再要求沉默超阈值、不再每日一次）；3.17.33 起默认开启阶梯想念（清醒沉默 6–20h / 20–48h / 48–120h，每阶段独立受理一次）。**120h 含在阶段 3 内，>120h 进入阶段 4（渗透模式）**：阶段 4 不再产生独立想念主动消息，改由早/午/晚安、刷QQ随口联系、视频分享等每日主动任务承载（先完成日常分享/问候，再沉下来反复确认对方是否还在）；用户下一次真实长回复回到阶段 0（<3 字/纯表情短回复只顺延起点、不重置周期）；`relation.silence_detected` 沉默事件与每日预算内的其他巡检行为不受该阶段窗口限制。日程主动巡检已删除（旧配置键升级时一次性 pop 退役）。
- 静默时段恒等于日程作息（入睡到起床），不需要单独配置。
- 可选：屏幕感知旁白、周结大事记、午休静默。

### 问候诊断（streams）

- `/lbm_diag streams` 的候选与序号按**三流分族**显示：「问候·群聊」「问候·其他私聊」「问候·目标私聊（无条件）」「频率调控」四块逐行输出，目标私聊流**回归诊断可见**（序号 = 群聊 → 其他私聊 → 目标私聊）。
- 检查窗 = 周期判定窗（上份日程开始 → 本份日程开始，非日历 0 点）；判定窗内查不到消息的群聊**不从候选中丢弃**，仍占一个 `#NN` 序号、行显「历史无消息」，行尾注明「硬闸窗内无消息·不发晨晚问候」。
- 带序号查询（`/lbm_diag streams <序号>`）与候选列表共用**同一序号系**；每流按早/晚各一行给结论（含「早安未开始（连锁待定）」「因早安未开口→晚安连锁硬性忽略」「连锁已通过」「数量闸达标 M/N」等档），下一行给判定窗端、阈值、冷静期余量等关键量。
- 诊断全链**纯读**：不写任何问候状态（掷点、连锁标记、事件缓存），不会干扰问候链自身的判定。

### QQ 空间

- 开启 `[qzone] enabled` 后，插件按日程节奏自动发说说。
- 发帖判定链：每日上限、发帖意愿与情绪闸、是否需要当前有活动、概率、静默时段、无活动、午休静默、冷却、模型严判、掷骰；拿不准就不发。当前活动与「是否有活动」读运行时真源，日程关断时如实按无活动处理。
- 配图有四种模式：`off`（不配图）、`emoji`（宿主表情包，出厂默认）、`library`（本地图库）、`random`（两者各半）。
- 任何一张图取不到都只跳过该图，全部取不到就发纯文本，配图失败不会阻断发帖。
- 自动回评；cookie 不可用时降级为「有新评论」提醒。点赞需手动 `/lbm_life qzone like`。
- 手动命令：`/lbm_life qzone post|comments|reply|like`；`decisions` 查看最近为什么没发。

### 情绪维护

- 情绪以愉悦度、唤醒度、支配感三个维度持续起伏，聊天中的大事件会带来冲击。
- 情绪为回复提供底色与文字描述，也会轻微影响主动频率与发帖意愿。
- 夜间进入睡眠窗后冻结，醒来时统一结算；有真实睡眠会话时以会话为准，无会话时按 tick 级空窗冻结入口兜底。
- `/lbm_init emotion` 由人设推导基线；`/lbm_emotion_config` 查看、`reset` 或 `clear`。
- 情绪映射与描述可在 `mappings/` 的对应表中调整。
- 情绪→生活反馈的每日回写预算在数据目录 `life_feedback_budget.json`：按**最终实际入账增量**检查并记账、保留逐轴净累计、单次上限 0.15；升级当天的旧 raw 记录无法可靠换算 actual 时**当日暂停新增生活反馈**（旧账原样保留、不重置额度），次日自动进入新口径。

以下工具由麦麦在对话中自行调用，无需手动输入：`lbm_get_schedule_info`（只读，支持 status/current/next/episodes/spine/intents 视图）、`lbm_update_schedule`（唯一日程写入口，写 spine 意图与未来约定）、`lbm_mai_lover_affection`、`lbm_report_harassment`、`lbm_life_qzone`、`lbm_emotion_report`、`lbm_watch_bili_video`（看B站视频：submit 提交 BV/链接，status/result 查询进度与真实结果，cancel 取消；后台有界执行，画面采样视本机 ffmpeg 与 vlm 任务可用性如实降级，观看完成绝不自动发消息）。3.0.0 已删除旧别名 `lbm_update_schedule_v4`、赖床工具 `lbm_nap_lie_in` 与 `lover_day` / `goals` 视图。

## 常见问题

- **升级到 3.0.0 后生活状态/睡眠不动了？** 检查 `[schedule] enabled` 是否为 `true`。旧 `[life_state] enabled` / `sleep_engine_enabled` 已退役，不会再被读取；若你曾显式关掉日程，升级后保持关闭。
- **日程变成了默认时段或明显被压扁？** 用 `/lbm_plan regenerate` 重新生成今日日意图即可。
- **早安或晚安没来？** 先用 `/lbm_diag streams` 查看候选流与序号，再用 `/lbm_diag streams <序号>` 查看该流下一次早安、晚安是否满足触发条件。群聊早安需要判定窗（上份日程开始 → 本份日程开始）内有人说话（必要性开关开启时今天日程第一个条目时段内也要有人开口），且早安没开口的当晚群晚安会被连锁拦下；其他私聊早安需要对方发送条数达门槛、晚安达标即可（连锁或阈值二选一）；过点才达标的补发还受冷静期约束（默认最近 3 分钟 bot 没说过话）。目标私聊无条件，但在 streams 里「无条件」族可见；没收到时用 `/lbm_dashboard` 或决策日志排查。
- **QQ 空间没发出去或没回评？** 用 `/lbm_life qzone status` 检查通道与 cookie，用 `/lbm_life qzone decisions` 查看最近卡在哪一道闸。
- **命令没反应？** 管理员命令要求 `[admin] admin_users` 中有你；`/lbm_mai_*` 只对 `[patrol] target_qq` 本人开放。`[admin] allowed_streams` 只约束 `/lbm_plan` 与日程注入，不影响其他命令。
- **只收到文字没有图？** 这是预期的降级：Pillow 或字体不可用、渲染超时时自动改发文字，功能不受影响。
- **想临时关闭某个模块？** 关闭 `[schedule] enabled`、`[patrol] enabled`、`[qzone] enabled`、`[affection] enabled` 或 `[emotion] enabled` 可分别停用对应模块；关闭 `[plugin] enabled` 会让全部模块停摆（含命令与工具）。
