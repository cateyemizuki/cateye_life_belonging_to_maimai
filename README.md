# 属于麦麦的生活

源码版本 **3.18.5**。这是 MaiBot 的生活与陪伴整合插件：日程与生活状态、虚拟陪伴、情绪、QQ 空间、视频观看和分享共用一套运行记录。本文说明源码已实现的能力；生产部署及自然运行验证以对应交付记录为准。

## 开始使用

1. 在支持插件清单声明版本的 MaiBot 中安装完整插件目录与依赖，配置可用的文本任务、需要画面理解时配置视觉任务。
2. 在「陪伴」配置目标 QQ。留空时只继承宿主唯一、可识别的 QQ 命令管理员；多管理员时不猜选目标。管理员列表留空会继承该陪伴目标，仍无法确定时只允许控制台。
3. 在「日程规划」设置起床、入睡锚点，在「日程高级」确认 IANA 时区。默认 `07:00`、`23:00`、`Asia/Shanghai`；这些是计划参考，不是已经睡着或醒来的事实。
4. 先用 `/lbm help` 查看真实可用入口；`/lbm plan list` 查看日程，`/lbm status dashboard` 看总览。初始化由 `/lbm ops init` 统一入口处理。
5. 按需要开启空间、自动屏幕感知、屏幕工具、视频自主观看和分享；各开关职责独立，见下表与[完整配置参考](CONFIGURATION.md)。

中文命令根为 `/麦麦生活`，与 `/lbm` 共用路由。管理命令受管理员与对应会话范围约束；具体子命令以帮助为准。

## 日意图、实际活动与约定

每天生成的是稀疏日意图，不是覆盖全天的执行日志。滚动规划根据窗口、硬约定和生活状态开始实际活动；对话注入与面板「此刻」读取运行中的活动，未就绪、空闲和已睡分开表示。

自动生成按配置时区、睡眠参考与已有日表推进，不按宿主时区固定钟点误算日期。未来日表先持久暂存，等待当前周期结束接替；首次查看缺少日表时也可发起生成。

最终候选包含模板、作息与硬约定后，再批量标注一次模块属性：`watch_video` 对应明确观看视频的活动；`browse_qq` 表示当前活动允许浏览 QQ，可来自明确逛 QQ，或可中断、低负担且适合顺便看消息的休闲活动。它不是已经浏览或收到消息的事实。没有充分依据或标注失败时为 `null`。模块属性与状态计算使用的 `goal_type` 分开；历史日程不按名称补写属性，名称或类型本身也不能证明真实观看或发过消息。

明确时间的硬约定由代码按稳定 ID 补齐并固定原时刻，睡眠和重排不会把它顺延。排入计划不代表兑现；只有实际完成证据或到期状态才结算，持久回执防止重启、重排和重试重复入账。日表替换与周期发布分开确认；周期未存好时继续补齐，不重复调用模型。

重新生成期间保留旧计划。候选发布前取消、超时或首次失败会保留已有日表；完整候选成功后才事务替换并归档旧行。实际执行历史不因重新生成而改写。

## 睡眠与午休

生活状态包括精力、饥饿、专注、压力、社交电量与睡眠债。夜间睡眠由真实睡眠会话与动态睡眠引擎管理，计划睡眠条目、已入睡、困倦和刚醒不会混为同一事实。

午休不是每天必排。现有窗口为 `13:00–15:15`，还要醒满三小时、达到困倦门槛并且没有当前活动占用或临近硬边界。诊断分别记录生理原因与活动阻挡，不能仅凭一条 `busy` 或一个「休息」名称认定已经午睡或错过午睡。

面板可以把睡眠、午休和分时用餐显示为更清楚的名称，但保留原名供查看；这是展示层处理，不改原日程、提示词、活动类型或执行记录。

## 自主观看与工具点播

| 入口 | 实际作用 | 开关与约束 |
| --- | --- | --- |
| 工具点播 | 用户或 bot 明确提供 BV/视频链接，提交、查询或取消观看任务 | 受 `video_watch.enabled` 观看总开关及读取/采样保护；不受自主选片热度门槛、自主场次和自主开关约束 |
| 刷视频属性日程 | 在真实进行中的 `watch_video` 活动内连续选片 | 保留睡眠、硬约定、忙碌与聊天守护；受该段剩余时间、支数及自主配额约束 |
| 闲暇日程顺便看 | 普通实际活动明确可中断且当前可响应时，独立判断是否看一支 | 每段仅掷一次并持久化；不是每个 tick 重试，也不是看到属性 `null` 就放行 |
| 空隙观看 | 无当前活动时的有界自主选片 | 有独立空隙次数与间隔，仍计入自主总额度 |

旧内置 `watch_bili`、`browse_qq` 事件保留兼容。`browse_qq` 属性在每段实际活动中只判断一次，保留原有 20% 可选社交机会，仍走目标、权限、预算、冷却与发送回执；不是每个 tick 重试，也不能绕过这些守护。

「视频自主观看」的出厂值如下，修改后以实际配置为准：

| 配置 | 默认值 |
| --- | --- |
| 启用自主观看 / 闲暇日程顺便看 | `true` / `true` |
| 每段日程观看概率 | `0.10`，每份原日表计划只判断一次 |
| 每日顺便观看上限 | `3` 场，每段最多一支 |
| 单段刷视频最多支数 | `10` 支 |
| 每日自主观看总场次 / 刷视频日程上限 | `8` / `4` 场 |
| 每日自主观看分钟上限 | `240` 分钟 |
| 每日空隙观看上限 / 最短间隔 | `2` 场 / `60` 分钟 |
| 主动选片播放量门槛 | `50000`，评论/投币/收藏默认 `0` 不检查 |

视频这里的“一段”以原日表计划身份（`schedule_date + intent_item_id`）累计机会和最多支数。暂停后恢复成新 episode 不重掷概率，也不重新获得十支；没有原计划身份的事件才按实际 episode 回退，并可沿 `resume_of` 继承。每日配额与运行 owner 仍按实际 episode 预留/结算，不复制一份日程状态。受理任务记录不等于已观看，未知受理会保留冻结预占，不记作已看完。这不改变浏览 QQ 原有的“每实际活动一次”语义。

顺便观看要求实际 `interruptibility >= 0.7` 且 `attention_mode=now`；缺值、默认 `0.5`、简短响应或稍后响应不会当成明确闲暇。仅对明确 `watch_video` 活动，`brief` 代表减少聊天响应，不中止它自己的视频续片；`later`、睡眠、硬约定、低可中断性、显式忙碌或真实来信仍会阻止。顺便观看和浏览 QQ 不使用该例外。

## 什么算真实观看

观看是有界采样理解，不宣称逐帧看完整片，也不做音频转写。默认 `stream` 直读媒体流，不先整片下载；`download` 是显式选择，受下载保护值限制。采样间隔、最小采样数和拼图上限可配置；超出准入容量会说明原因，不静默稀释采样。

工具 `lbm_watch_bili_video` 提供提交、状态、结果、取消等动作。观看队列、媒体读取、视觉理解、内容描述和观后感有各自阶段；失败、取消或通道不可用会如实标记。只有标题简介时，不把元信息当成真实画面理解，也不据此伪造完整观后感或强行自动分享。

娱乐页区分封面、观后感、点赞/投币/收藏和数据来源。观看记录时间取任务受理时刻，不等于媒体处理完成或 API 数据采集时刻；第一次、最近一次观看与采集时间分别展示。缺失数据说明「未记录」，明确回传的零保持为零。

旧观看记录可由后台只读请求补齐缺失标题、封面和统计，标为「历史补录 · 当前数据」。补录不会重新观看、调用理解模型、改变观看时间或延长原缓存期限，也不会凭空生成缺失的真实理解。

## 分享、空间与屏幕的边界

- **观看与发送分开**：任务完成本身不直接发消息。视频分享由独立判定和投递链决定，允许不分享、延后或结果未知时保守防重。
- **视频聊天分享**：`video_share.mode` 出厂为「自动分享」，`allow_all_groups=true`；实际可用目标仍受会话画像、活跃门槛、模型决定、次数、间隔和发送守护。希望先观察可改为「影子模式」，完全停用可改为「关闭」。
- **QQ 空间**：`qzone.enabled` 默认关闭；视频空间链 `qzone_video.mode` 默认 `shadow`，与聊天视频分享不是同一个开关。自动空间发布仍受静默、冷却、额度与内容判定。
- **历史动态图片**：后台仅对已确认自己发送的动态只读取图并独立缓存，展示接口返回并通过协议校验的图片地址，沿用原动态访问权限和链接时效；图片仍可能受可见范围、鉴权或时效限制，不因 URL 校验而获得公开授权。补图不改变发布成功回执，不重发动态。打开面板不会因此发帖、发消息或观看视频。
- **屏幕感知**：`screen.enabled` 自动感知和 `screen.tool_enabled` 窥屏工具均默认关闭，互相独立。启用后屏幕画面交给已配置视觉任务理解；默认主屏、模糊半径为 `0`。窥屏工具限陪伴目标私聊，群聊和其他私聊不提供此能力。

## 面板与排查

生活面板分别展示此刻、日意图、实际足迹、状态/心情历史、观看记录、空间和模型用量。活动模块属性单独显示，图片与数据缺失有明确占位；展示名称不改变原始业务数据。娱乐页右上角切换视频与动态，两页以多张卡片并列展示，按当前列数最多加载约三行；日程和历史仍可按日期查看。视频卡显示播放量、点赞、投币、收藏及来源；长标题、观后感和动态正文以省略号预览，点击卡片可查看完整详情与图片。历史存储和原文保留。

心情曲线可以独立选择 6 小时、24 小时、3 天或 7 天并放大/全览，不跟着生活状态曲线一起改变范围；悬停或触屏轻点显示实际点值，离开或点外收起。

小鱼和桌宠是浏览器端交互，形象选择显示「萨卡班麦麦 / 麦麦」；收起、动效与位置等本地设置不等于关闭服务端日程或主动行为。页面采用只读快照，隐藏时暂停或降低刷新，减少动态设置按浏览器偏好生效。

若配置列表仍显示内部键/序号，应区分宿主表单的标签渲染与插件配置内容。配套修正须匹配实际已安装的宿主版本/资源基线，本批提供标签与本插件受限图片策略两个独立配套补丁；各批安装状态、备份及包路径以交付报告为准，不把标签批已安装当成图片批也已安装，不能用任意同版源码整包重建替换。

受限图片策略仅由宿主可信的本插件 ID 启用，为图片追加有限 HTTPS CDN：`hdslb.com`、`biliimg.com`、`qpic.cn`、`photo.store.qq.com`、`gtimg.cn`、`gtimg.com` 及其允许子域。页面自称插件身份不能取得权限；其它插件政策和 `connect/script/frame/font` 不放宽。已知 CDN 的 HTTP 图片地址提升为 HTTPS，非白名单不自动放开，失败保留缺失占位。该策略也不改变原动态的可见范围或鉴权。

模型调用与生成结果共用记录：只统计实际发出的请求，模板不增加调用和 Token；Token 只记宿主明确回传的数据，缺失不推算。调用/生成判断保留三十天，页面裁剪不改变历史分类。日志可能包含模型返回文本或业务诊断，不承诺只有计数。

常用排查入口：`/lbm diag rolling` 查看实际滚动/睡眠，`/lbm diag streams` 查看问候候选与条件，`/lbm diag llm` 查看调用与模板来源。先确认配置和真实状态，再看失败回执；空计划、空闲、暂未就绪、缺少真实观看结果不混写成成功。

升级后若娱乐页所有图片都显示“图片暂时无法加载”，可先按 `Ctrl+F5` 强制刷新面板，重新加载页面及图片策略。仍失败时再检查浏览器对图片站点的限制与网络连接。
